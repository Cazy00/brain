# `brain serve` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make the brain reachable from another device, without weakening anything about how it works locally. `bin/brain-mcp` is stdio-only, and stdio has no URL — which is why "just send them the connection link" is impossible today and why remote access and the tunnel request are the same feature.

**Predecessors:** [2026-07-25-setup-foundation.md](2026-07-25-setup-foundation.md) (stages 1–3) and [2026-07-29-connect-retire-docs.md](2026-07-29-connect-retire-docs.md) (stages 4–6), both closed 2026-07-29. This is stage 7 of [the spec](../specs/2026-07-25-setup-ux-redesign-design.md), and the last of it. It depends on nothing in the other two beyond the keystore backend Plan 1 built.

**Architecture:** HTTP is added **alongside** stdio, not instead of it. Local use does not change: stdio stays the default and every existing client keeps its existing registration.

That forces one structural decision. Two transports must expose the *same* tools, or the remote brain quietly becomes a different brain — a tool present on one and missing on the other is a bug nobody would find until somebody far from their laptop needed it. So the tool layer moves out of `bin/brain-mcp` into `bin/brainlib/mcp.py`, `bin/brain-mcp` becomes the stdio entry point, and the HTTP transport is a second caller of the same `handle()`. The shared function returns a reply rather than writing one, which is also what lets HTTP tell a request (answer it) from a notification (202, no body).

**Tech Stack:** Python 3.9+ standard library only — `http.server.ThreadingHTTPServer`, `hmac.compare_digest`, `secrets`. No framework, no TLS: TLS is the tunnel's job and saying so is part of the contract.

## Global Constraints

These apply to every task. Violating any of them fails review.

- **Python 3.9 floor.** No `match`, no `X | Y` unions at runtime, no `dict1 | dict2`, no `str.removeprefix`.
- **Zero third-party dependencies.** `bin/brain-mcp` advertises "zero dependencies and no vendor SDK" and that claim is load-bearing.
- **The stdio path does not change.** Every existing `McpServerTests` case must pass **unmodified**. If one needs editing, stop — the refactor is wrong.
- **No credential ever reaches the repo.** `brain lint` refuses credentials in tracked files and that rule is not being weakened for this. The token lives in the OS keystore; tests use a `FileKeystore` pointed at a temp directory.
- **No test may bind a public interface.** `127.0.0.1`, port 0 (ephemeral), always.
- **All dates in code, comments and docs are absolute** (`2026-07-29`), never "today".
- **The commit gate runs on every commit.** `.githooks/pre-commit` runs `python3 bin/brain lint --staged` plus `gitleaks`.
- **Existing tests must keep passing.** 407 as of 2026-07-29, minus the one known environment-specific failure (`test_init_defers_when_claude_cli_absent`, which fails only on a machine with `claude` in `/usr/bin`; it is not caused by this work and must not be "fixed" by weakening its assertion).
- **Match the surrounding prose style.** Comments explain *why*, especially why an obvious alternative was rejected.

## The security contract, in one place

This is the only thing in this repo that opens a socket, and the tool behind it includes `brain_capture`, which **writes**. Every item below is a hard requirement, and each has a test.

1. **Refuses to start without a token.** A refusal, not a warning. The message names the command that mints one.
2. **Every request requires `Authorization: Bearer <token>`.** Compared with `hmac.compare_digest` — a naive `==` leaks the token one byte at a time to anything that can measure a response.
3. **Default bind is `127.0.0.1`.** Any other bind requires an explicit flag and prints what it is exposing.
4. **The `Origin` header is rejected outright** unless explicitly allowed. The MCP transport spec makes Origin validation a MUST for exactly one reason: a page on `evil.com` can make a browser talk to `127.0.0.1`. No legitimate client of this server is a browser, so the allowlist is empty by default. This is the second barrier, not the first — a cross-origin request cannot set `Authorization` without a preflight either — and two independent barriers is the point.
5. **The token lives in the OS keystore**, per platform (Keychain / secret-tool / Credential Manager / a 0600 file), never in the repo, never in a config file, never in a URL.
6. **`brain_capture` is reachable over this transport.** It is a write tool. The docs say so plainly, in the section that tells you how to expose it. A read-only serving mode is future work and is not built here.
7. **No TLS, on purpose.** The tunnel terminates TLS. Serving plaintext on loopback is correct; serving plaintext on `0.0.0.0` is the user's explicit choice and the flag says so.

## The open question, resolved

The spec left one thing to verify rather than guess: whether claude.ai custom connectors accept bearer-token auth or require full OAuth 2.1. Checked against primary documentation on 2026-07-29:

- **Claude Code: yes.** `claude mcp add --transport http brain <url> --header "Authorization: Bearer <token>"` is documented, current, and exactly what this server speaks.
- **claude.ai web, Claude Desktop and mobile: no, not for an individual.** Anthropic's connector documentation lists `static_headers` (a fixed API key or bearer token as a request header) as **beta**, entered by an **organization administrator** when adding the connector. The per-user "add a custom connector by URL" flow offers only OAuth Client ID and Client Secret. A pure bearer-token server is therefore not consumable there today by one person on a personal plan.

So this plan ships the bearer-token server, documents Claude Code and any client that can set a header as the supported path, and states the claude.ai position as a fact with its date rather than a promise. OAuth 2.1 with DCR or CIMD is what would close that gap; it is a much larger piece and it is not in this plan.

### Task 2: The HTTP transport

**Files:**
- Create: `bin/brainlib/serve.py`
- Test: `tests/test_serve.py`

**Interfaces:**
- Consumes: `brainlib.mcp.handle`, `brainlib.osbackend.keystore`.
- Produces:
  - `make_server(token, host, port, allow_origin=()) -> ThreadingHTTPServer`
  - `TOKEN_NAME = "brain-serve-token"`, `mint_token()`, `read_token()`, `store_token(value)`
  - `ENDPOINT = "/mcp"`

Conformance, from the MCP Streamable HTTP specification (2025-06-18), which is the part that decides whether real clients connect:

- One endpoint (`/mcp`) supporting POST; GET and DELETE answer **405**, which the spec explicitly permits for a server that offers no SSE stream. Any other path is **404**.
- A POST whose body is a JSON-RPC **request** returns `Content-Type: application/json` with a single JSON object. (SSE is optional; this server does not stream, and saying so with a 405 is compliant.)
- A POST whose body is a **notification** or **response** returns **202 Accepted** with no body.
- An unparseable or oversized body returns **400**. The cap is the same 10 MB the stdio loop already uses: a bigger single request is not real traffic.
- `MCP-Protocol-Version`, when present and not a version this server has been checked against, returns **400** — the spec's MUST. The checked list is a literal in the code, so widening it is a deliberate edit.
- Session IDs are not used. They are a MAY, and a stateless server has nothing to keep in one.

### Task 3: The token, and `brain serve` in the CLI

**Files:**
- Modify: `bin/brainlib/serve.py` (add `run_serve`)
- Modify: `bin/brain` (module docstring, `main()` dispatch)
- Test: `tests/test_serve.py`

```
brain serve                    serve on 127.0.0.1:<port>
brain serve --new-token        mint a token, store it, print it ONCE
brain serve --bind 0.0.0.0     explicit, warned, opt-in
brain serve --port <n>
```

Details that matter:

- Without a stored token, `serve` **exits non-zero** and prints `brain serve --new-token`. It does not mint one silently: a token that appears without anybody seeing it is a token nobody knows to protect.
- `--new-token` prints the token once and says so. It replaces any existing token, and says that too — every client wired to the old one stops working, which is the correct behaviour for a rotation and a surprise if unannounced.
- The startup banner prints the exact client registration command with the token as `$BRAIN_TOKEN`, **not** the token itself. Printing the real one on every start writes it into scrollback, terminal logs, and any screen recording.
- `--bind` anything other than a loopback address prints what it is exposing, on stderr, before serving.

## Self-review

**Spec coverage for stage 7.** HTTP alongside stdio → Task 1. `brain serve` / `--new-token` / `--bind` → Tasks 2, 3. Refuses without a token, constant-time comparison, loopback default, keystore storage → Task 2 and Task 3, one test each. The write tool stated plainly → Task 4. The tunnel contract without a provider → Task 4. The open question → resolved above, from primary docs, with the date.

**What this deliberately does not do.** No TLS (the tunnel's job). No OAuth (what claude.ai would need; a much larger piece). No read-only mode (spec calls it future work). No SSE streaming (optional in the transport spec; a 405 on GET is the compliant way to say a server does not stream). No session IDs (a MAY, and this server is stateless). No rate limiting — worth revisiting the moment anyone runs this on a public bind for real.

**The risk that is real.** This is the only socket in the repo, and `brain_capture` behind it writes to a git repository that auto-pushes. The mitigations are a mandatory token, a loopback default, an empty Origin allowlist, and documentation that states the exposure where the decision is made. What is NOT mitigated: anyone holding the token can write. That is the design, it is what a personal remote brain means, and the docs say it in those words rather than implying otherwise.
